# 蜗牛4K 精选 → 115 转存工作台

把 [wn4k.com](https://www.wn4k.com)（蜗牛 I 4K）上的 115 资源，**按类型分类、按各种信息排序、逐条确认后**转存到你自己的 115 网盘，并按
**分类 / 类型 / 年份 / 片名** 自动建好目录。

> 这个工具不是「全站爬虫」。它只抓你正在看的那一页，并且转存前一定让你确认。

**TL;DR（给人类）**
```bash
python -m pip install -r requirements.txt
python -m app.server          # Windows 也可双击 start.cmd
```
浏览器打开 <http://127.0.0.1:8848> → 右上角「登录设置」→ 登录蜗牛 + 扫码登录 115 → 挑片 → 转存。

**TL;DR（给 AI agent）**
- 这是**本地单人**工具：FastAPI 后端 `app/server.py` + 原生前端 `web/`，无构建步骤。
- 凭证只存 `data/config.json`（已 gitignore），**明文密码不落盘**，只存会话 Cookie。
- 转存走 **115 网页版 Cookie 鉴权** `POST webapi.115.com/share/receive`；**开放平台 token 不支持转存**。
- 关键参数易错点：`file_id` 是**分享内**的文件 id，目标目录是 **`cid`**。
- 安全上限在 `app/config.py` 的 `DEFAULTS["safety"]`（单次 30 部 / 60 条），**超限报错不截断**。
- 自检：`python selftest.py`（只读站点少量页面，**从不向 115 写入**）。

## 目录结构（自动分层）

转存时会在你选定的目标目录下，按模板逐级创建子目录并转入。默认：

```
电影/动作/1984/终结者
电影/音乐/2017/缝纫机乐队
连续剧/其他/2014/养父的花样年华
```

模板可改（界面上就能改，带实时预览）：

| 占位符 | 含义 |
| --- | --- |
| `{category}` | 分类：电影 / 连续剧 / 综艺 / 动漫 |
| `{genre}` | 类型：动作 / 科幻 / 喜剧…（关键词推断，见下） |
| `{year}` | 年份 |
| `{title}` | 片名 |
| `{region}` | 地区（US、CN…） |
| `{quality}` | 清晰度（4K WEB、1080P蓝光原盘…） |

例：`{category}/{year}/{genre}/{title}` → `电影/1984/动作/终结者`

> 名称会自动清洗：去掉 `<>:"/\|?*` 等非法字符、首尾空格和点、超长截断（115 不允许 `<>`）。
> 空占位符所在的层级**自动跳过**，不会产生 `//` 或名为 `{unknown}` 的目录。

### 关于「类型」这一层

**站点数据库里有真实的类型字段，且支持服务端筛选**，但模板没把它渲染到页面上。

实测依据（对照实验，不是猜测）：

| 请求 | 结果 | 说明 |
| --- | --- | --- |
| `/vodtype/1/?class=动作` | 97 页，结果集与基准明显不同 | 真实筛选 |
| `/vodtype/1/?class=喜剧` | 118 页，结果集不同 | 真实筛选 |
| `/vodtype/1/?class=zzzz乱码xx` | **0 条** | 证明不是被忽略的参数 |
| `/vodtype/1/?year=2026` | 整页 36 部**全部**是 2026，共 21 页 | 严格筛选 |
| `/vodtype/1/?area=US` | 整页**全部**是 US | 严格筛选 |

但详情页**不显示**类型（`.p-tag` 只有 `评分/年份/地区/分类/清晰度`），
`/vodshow/1--动作--/` 路由也是 404，所以类型只能通过 `?class=` 查询参数拿到。

因此类型有两条来源，**优先级如下**：

1. **服务端真实类型（权威）**：当你在界面里按「类型」筛选后转存，
   选中的类型会直接作为目录名，不做任何猜测。
2. **本地关键词推断（回退）**：没按类型筛选时，用 `data/genre_rules.json`
   的关键词表推断。片名权重 3 分、简介 1 分、标签 1 分；**没有命中就归「其他」——不猜**。

> 想让类型 100% 准确：先在界面上点类型筛选（如「动作」），
> 再从中挑片转存，这样用的就是站点真实类型。
> 直接跨类型批量转存时，才会退回关键词推断。

站点实测存在的 21 个类型：
动作 / 喜剧 / 爱情 / 科幻 / 恐怖 / 悬疑 / 惊悚 / 剧情 / 战争 / 犯罪 / 冒险 /
奇幻 / 动画 / 纪录 / 历史 / 音乐 / 家庭 / 运动 / 传记 / 伦理 / 古装

规则文件 `data/genre_rules.json` 可在界面点「类型规则」编辑，改完立即生效；
想恢复默认就点「恢复默认」或删掉该文件重启。

### 筛选是服务端的（重要）

分类、年份、地区、类型、站内排序**全部由站点服务端完成**，不是本地过滤当前页。
所以选「2026」拿到的是**全站该年份**的结果（21 页），而不是只筛当前那 36 条。

> 早期版本是本地筛选，会导致「2026 只筛出 4 部，而明明还有其它 2026 的片找不到」——
> 因为第 1 页恰好只有 4 部是 2026。现已改为服务端筛选，此问题不再存在。

## 为什么是 Python 而不是 Spring Boot

- 本机 Java 是 **1.8**，而 Spring Boot 3.x 要求 **JDK 17+**；Python 3.10 环境（FastAPI / requests / bs4 / lxml）已就绪。
- 抓取 + 解析 + 编排属于轻量 IO 密集场景，Python 更省事，也方便你日后自己改。

## 为什么 115 用 Cookie 而不是开放平台

这一点很关键，也是设计上的硬约束：

- **115 开放平台（open.115.com）没有提供「分享转存」接口**，只有上传/下载/离线下载等能力（`proapi.115.com/open/...` 需要 Bearer token）。你自建的 `yun.afann.xyz` 走的就是这条路，所以它只有上传/下载，没有转存。
- 网页版点「转存」时调用的是 **`POST https://webapi.115.com/share/receive`**，属于 **Cookie 鉴权**。

所以本应用通过**扫码登录**或**粘贴 Cookie** 取得网页版会话，才能做转存。
（接口参数已对照 [ChenyangGao/p115client](https://github.com/ChenyangGao/p115client) 源码逐一核实。）

⚠️ 一个容易踩的坑：`share/receive` 里 **`file_id` 是「分享内」的文件/目录 id，目标目录叫 `cid`**，两者含义不同。

## 登录

### 蜗牛站点（必须，否则看不到网盘链接）
站点对游客隐藏网盘链接（详情页显示「登录后可查看完整网盘链接」）。两种方式：

- **账号密码**：点右上角「登录设置」→ 填账号密码 → 登录站点。
- **Cookie 导入**：浏览器登录站点后，F12 → Network → 复制任一请求的 Cookie 整串粘进去。

> 站点若开启验证码，账号密码方式会失败并明确提示，此时请用 Cookie 导入。
> 明文密码**不会**落盘，只保存会话 Cookie 到 `data/config.json`。

### 115（转存必须）
点「登录设置」→「生成二维码」→ 用 **115 App** 扫码确认。
也可以手动粘贴 115 网页版 Cookie。

> 扫码接口 `app="web"` 较容易触发「IP 登录异常」（需次日 0 点解禁）。真遇到就改用 Cookie 粘贴。

| 你的需求 | 在哪用 |

| 按键筛选 | 筛选区：**类型**（站点真实 21 类）、**年份**、**地区**，每类独占一行 |
| 排序 | **站内排序**（时间/评分/热度，服务端）+ **本地排序**（评分/年份/清晰度/片名/最新） |
| 翻页 | **底部翻页条**：上一页 / 下一页 / 跳转到第 N 页；也可**向下滚动自动加载** |
| 点进详情看简介 | **左键点卡片** → 弹出简介、导演、主演、更新时间与全部资源条目 |
| 单条转存 | 详情页每条资源右側「转存」按钮 |
| 多选转存 | **右键**卡片（或 Ctrl/Shift + 左键）勾选，右上角「转存所选」 |
| 选择转存到哪个目录 | 转存弹窗里可**逐层浏览** 115 目录并切换 |
| 新建目录 | 转存弹窗里「新建文件夹」，在当前目录下创建 |
| **按类型/年份/片名自动建目录** | 转存弹窗「目录结构」输入模板，下方实时预览实际路径 |
| **调整类型判断规则** | 转存弹窗「类型规则」按钮，编辑关键词表 |

### 翻页说明

**只用底部翻页条**：`← 上一页` / `第 N 页 / 共 M 页` / `下一页 →`，另有「跳到第 N 页」。

每次翻页只加载一页（36 条），语义清晰、行为可预期。

> 早期版本还做过「向下滚动自动加载」，但它的提示文案会误导：只要滚到接近底部就
> 无条件显示「正在加载下一页…」，覆盖掉真实状态（例如已达单次上限），
> 看起来就像永远卡在加载。既然翻页条已经够用，就把它移除了——
> 少一个会撒谎的组件。

### 筛选区说明

四种筛选各占一行：**类型 / 年份 / 地区 / 排序**，全部走站点服务端。

- **类型**：站点真实 21 类（实测枚举，非关键词猜测）
- **年份**：常见年份直接点；任意年份用右侧**输入框**（如填 `1994` 回车）
- **地区**：站点真实 57 个，显示中文
- **排序**：按时间 / 按评分 / 按热度

**选项上刻意不显示数量。** 因为数量只能统计「当前页」，而点击后是站点**全站**检索，
两者口径不同——显示数字必然与实际结果对不上（例如标「美国 12」，点开却是 189 页）。

**筛选项都用站点完整清单，而不是「当前页出现过的值」。** 这点很关键：
早先年份是从当前页提取的，导致第 1 页没有 1994 就永远选不到 1994，
而实际上全站有 7 页 1994 的片子。现在类型/地区用完整清单，年份还额外给了输入框，
这类「选不到」的问题不会再出现。

**地区显示为中文，但查询值不变。** 这不是多余的设计：实测 `area=US` 有 189 页，
而 `area=美国` 只有 38 页，**两边结果 ID 重合 0 条**——站点数据库里 ISO 码和中文名是
**两批不相交的记录**。所以显示可以翻译，查询值绝不能替换，否则结果会变。
界面上的筛选状态会同时显示中文与原始值（如 `筛选：地区 US`），便于核对。

### 搜索有 3 秒频率限制（重要）

站点对**搜索**单独限流，被拦截时返回的是「跳转提示」页而非搜索结果，
页面上原话是「**请不要频繁操作，搜索时间间隔为 3 秒**」。

程序的处理：

- 搜索之间**强制间隔 3.4 秒**（全局节流，连点也不会超）
- 识别出拦截页就**等待重试**，最多 3 次
- 仍被拦截则明确报错「请稍等几秒再搜」，**绝不伪装成「没搜到」**
- **空结果不写入缓存**——这条最关键：「0 条」既可能是真没收录，也可能是被限流，
  一旦把后者缓存下来，就会在 TTL 内一直谎报「搜不到」

> 早期版本正是踩了这个坑：被限流时静默返回 0 条并缓存，于是同一关键词时好时坏
> （实测连续搜 6 次只有 1 次有结果）。现已修复，自检含连续 3 次搜索的回归用例。

### 详情页可直接复制网盘地址

点开影片详情，每条资源都显示**真实网盘地址**（如
`https://115cdn.com/s/sww0n3q3wxq?password=j2b1`），提取码单独标出，**点击即复制**，
或用右侧「复制链接」按钮——方便分享给他人。

未登录站点时地址不可见（显示「登录后可见」），因为站点本身对游客隐藏。

### 115 登录会过期

115 网页版 Cookie 有效期有限，过期后 115 会返回「请先登录,后操作！」。
界面顶部的 115 状态会自动探测并显示「未登录」，重新扫码即可。

转存弹窗里先点 **「预览将转存的内容」**，看清楚要转什么、**转到哪个目录**，再点「确认转存」。

## 关于「不批量拉全站」

这不是靠自觉，而是代码里写死的：

1. **列表只取当前页**，想多看只能点「加载更多」，且**单次请求最多 5 页**（`MAX_PAGES`，超出直接 422 拒绝）。
2. **详情页只在两种情况抓取**：你点开某片，或该片进入转存计划。不会后台遍历。
3. **转存有硬上限**：单次最多 `max_batch=30` 部影片、`max_links_per_batch=60` 条链接；超限**直接报错**而不是默默截断。
4. **全局限速**：对站点默认最小间隔 1.5 秒（带抖动）+ 失败退避重试；115 侧 1.2 秒。
5. **本地缓存**：列表 30 分钟、详情 1 天，重复浏览不再打站点。
6. **默认只挑 1 条可用链接**：勾选一部影片时不会把它那 30 多条资源一起转走，需要多条时请在详情页逐条点。

```json
// data/config.json 里可调（也可改 app/config.py 的 DEFAULTS）
{
  "wn4k":  { "min_interval": 1.5 },
  "p115":  { "min_interval": 1.2, "default_cid": "0" },
  "safety":{ "max_batch": 30, "max_links_per_batch": 60 }
}
```

## 常见问题

**双击 `start.cmd` 报「'd' 不是内部或外部命令」或满屏乱码？**

这是批处理文件的编码/换行被改坏了。`start.cmd` 必须是 **CRLF 换行 + 系统 ANSI(GBK) 编码**，
否则中文 Windows 的 cmd.exe 会解析错乱（`cd /d` 被拆成 `d`）。

仓库里的 `.gitattributes` 已把 `*.cmd` 标记为 `-text`（二进制、不做任何转换），
所以正常 clone 或下载 ZIP 都不会有问题。**如果你手动编辑过这个文件**，请确保：

- 换行是 CRLF（不是 LF）
- 编码是 ANSI/GBK（不是 UTF-8）

或者干脆不用它，直接命令行启动：

```powershell
cd C:\Users\lijuefan\Desktop\zhihui\wn4k-115
python -m app.server
```

**115 显示「未登录」？** 网页版 Cookie 有有效期，重新扫码即可（见上文「115（转存必须）」）。

**搜索偶尔说没结果？** 站点对搜索有 3 秒频率限制，程序已自动节流与重试；
若仍提示受限，等几秒再搜即可（见上文「搜索有 3 秒频率限制」）。

**端口 8848 被占用？** 说明已有一个实例在跑，直接开浏览器访问即可；
想换端口就改 `data/config.json` 里的 `ui.port`。

- **磁力/电驴**走的是 115「离线下载」（`clouddownload.115.com/lixianssp/`），需要登录且有配额；该接口非公开文档，115 可能调整。站点里标注「115离线下载」的资源组多为这类链接。
- 百度网盘等**非 115 资源**不会转存，会在预览里明确标为「不支持」。
- 115 网页接口非官方公开 API，若 115 调整，`app/p115.py` 里的接口需同步更新（文件头已列出全部接口依据）。
- 仅供个人备份自己有权保存的内容，请遵守站点与 115 的服务条款。
